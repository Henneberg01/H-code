# WebSocket chat implementation plan

> **For agentic workers:** Use superpowers:executing-plans inline with a final independent review.

**Goal:** Prove immutable Canonical17 room chat over actual WebSocket clients.
**Architecture:** Generic pure event reducer plus maintained transport; independent
TS chat owns its own state/routing. Source-locked actual wire traces derive readiness.
**Tech stack:** Rust frontend, independent JS evaluator, Node 22.13+, pinned ws8.22.0.
**Spec:** `docs/superpowers/specs/2026-10-20-websocket-chat-design.md`.

## Global constraints

Preserve all prior frozen sources and original20 IDs/acceptance. No global70 claim.
Generic operation: ⇄/websocket_serve, Function,String→Unit. Event client/data/kind;
output messages(client/data records)/state. State1MiB,64peers/messages,
16,384message bytes,65,536queued bytes,128header pairs. Explicit loopback grant.

## Review focus

- Disconnect races must not leak rooms or crash unrelated peers.
- Pure callback checks must follow helper functions and every nested operand.
- Output must be fully validated before state changes or any message is sent.
- Burst delivery order and Unicode length/byte boundaries must agree in all paths.
- Negative wire proof must observe synchronization, never pass on a startup failure.
